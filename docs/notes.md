# Notes / Knowledge Base

Notes 用于持续修订的知识笔记，Blog 用于完整文章。两者共用内容编译、正文样式、目录、公式、代码复制和文末签名，但 Notes 按文件夹归类，支持正文搜索与反向链接。

## 添加第一篇笔记

1. 在 `content/notes/` 下创建主题目录，例如 `机器学习/`。
2. 新建 `入门.md`，填写标题、摘要和正文。
3. 运行 `npm run dev`，访问 `/notes/` 查看分区与阅读页。
4. 提交前运行 `npm run check`，确认元信息、附件和互链有效。

```markdown
---
title: 梯度下降笔记
description: 记录更新公式、步长选择和待验证的问题。
tags: [优化, 机器学习]
---

## 问题

需要最小化什么目标？

## 推导

参数更新为 $x_{k+1}=x_k-\eta\nabla f(x_k)$。

## 待验证

- [ ] 用一个简单函数检查更新方向
```

不需要修改 React、手工登记目录或保留模板文章。目录为空或不存在时，页面显示空列表，构建仍可完成。开发模式新增、修改和删除笔记后会刷新索引。

## 分区与路径

分区由 `content/notes/` 下的第一层文件夹决定，YAML 的 `section` 不会覆盖它。

| 文件位置                        | 分区        | 阅读地址                                    |
| ------------------------------- | ----------- | ------------------------------------------- |
| `source/ta_timestep_control.md` | Source code | `/notes/?post=source%2Fta_timestep_control` |
| `机器学习/入门.md`              | 机器学习    | `/notes/?post=机器学习%2F入门`              |
| `机器学习/深度学习/网络.md`     | 机器学习    | `/notes/?post=机器学习%2F深度学习%2F网络`   |
| `零散想法.md`                   | Other notes | `/notes/?post=零散想法`                     |

浏览器会自动编码中文地址。文件名及相对路径决定地址，改标题不会改变地址；移动文件或重命名目录会改变地址。分区名支持中文、英文、空格和标点，保留大小写，请保持命名一致。

`src/config/sections.mjs` 为 `source` 和根目录笔记提供展示名称与介绍，其他主题直接使用文件夹名。只有包含已发布笔记的分区才会出现；草稿、空目录、以 `_` 或 `.` 开头的文件与目录不创建分区。预设分区排在前面，其余分区按名称排序；每个分区中的笔记按标题排序。

## 元信息与日期

元信息规则与 Blog 共用，详细说明见 [文章撰写](writing.md)。常用字段如下：

| 字段               | 用途                                           |
| ------------------ | ---------------------------------------------- |
| `title`            | 笔记标题；省略时取首个一级标题，再回退到文件名 |
| `description`      | 列表摘要；省略时取第一段正文                   |
| `tags`             | 标签列表，点击标签可搜索                       |
| `author` / `email` | 可选作者和联系邮箱，留空时隐藏                 |
| `date` / `updated` | 可选发布时间和编辑时间                         |
| `draft: true`      | 排除发布，也不会进入全文搜索和反向链接         |

Notes 不使用 Blog 的列表置顶与日期排序控件。日期统一显示 `Posted on`，有后续编辑时显示 `Edited on`。省略日期时使用 Git 历史；重命名本身不产生编辑日期，但修改正文会产生。没有 Git 历史时的本地回退与有效格式见 [日期规则](writing.md#发布时间与编辑时间)。

## 笔记互链与反向链接

同一集合内使用 Markdown 文件的相对路径：

```markdown
[同目录的另一篇](./another-note.md)
[步长控制](../source/ta_timestep_control.md)
[另一篇的指定章节](./another-note.md#section-example)
```

这些写法是语法示例，目标文件必须实际存在。构建将 `.md` / `.html` 链接转换为阅读地址，并拒绝不存在、草稿或被排除的目标。章节锚点可以从实际阅读页目录链接复制；重名标题可能带序号。

阅读页末尾的 `Notes linking here` 自动列出链接到当前笔记的其他笔记，同一来源只列一次，自身引用不计入。没有来源时显示空状态。查询式站内笔记链接也参与反向链接识别，但跨 Blog 的链接不会成为 Notes 的反向链接。

跨集合使用明确的站点路径，例如：

```markdown
[关于 AI 的文章](/blog/?post=thoughts_on_ai)
```

## 搜索与阅读

- 搜索覆盖标题、摘要、分区展示名称、标签和正文，使用不区分大小写的完整子串匹配，忽略查询两端的空白。
- 首次输入非空关键词时才加载全文索引，浏览列表和直接打开正文不会下载该索引。
- 搜索条件保存在 URL 的 `q` 参数中。点击搜索结果、反向链接并返回列表时会保留关键词；刷新也可恢复。
- 全文索引加载失败时显示重试入口；空结果可以清空查询后重新浏览。
- 正文按篇加载。数学样式仅在含公式的文章中加载，Mermaid 在图表接近视口时才渲染。
- 文末签名约 6.3 秒写完，进入视口后才初始化动画；减少动态效果与打印使用同一套静态笔画。

## 附件、迁移与删除

笔记附件放在内容目录内，使用相对路径引用，例如 `./assets/trace.webp`。全站共享图片放在 `public/images/`，以 `/images/文件名` 引用。相对附件会被校验并打包，`public/` 资源则需自行确认文件存在。

移动或删除笔记时：

1. 搜索旧文件名、旧 slug 和指向该文件的相对链接。
2. 更新其他笔记的引用；同时更新维护文档或外部已发布链接。
3. 删除不再被任何文章引用的专属附件；共享附件需先核对所有引用。
4. 运行 `npm run check`，检查 `/notes/`、正文、搜索和反向链接。

旧地址不会自动重定向；地址稳定性有要求时优先保留文件路径，只修改标题与正文。删除一个分区的最后一篇笔记后，可直接移除空目录。

## 维护与测试

发布目录只保留实际笔记。已移除的模板和示例不再参与网站构建；编译、分区、全文搜索、互链和空目录测试均使用内联样例或临时目录，不依赖某篇线上文章或固定笔记数量。可以继续添加或删除主题，无需为测试保留占位文件。
