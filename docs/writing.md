# 如何写一篇手记

将 `.md` 或 `.html` 文件放进当前 `content/blog/` 目录（也可按年份建立子目录）。开发时保存后自动更新；发布时重新运行构建并推送即可。无需修改 React 代码或文章列表。

## Markdown

新建 `my-note.md`：

````markdown
---
title: 我的第一篇手记
author: Alicia
email: alicia@example.com
date: 2026-09-19
description: 一句话描述文章内容。
tags: [学习, 随记]
section: 学习
pin: false
---

# 我的第一篇手记

从这里开始写正文。上面的同名一级标题不会在页面重复显示。

## 一个小标题

支持 **加粗**、_斜体_、[链接](https://example.com)、列表、引用、表格、任务清单、图片、脚注[^note]，以及 `$E=mc^2$` 与独立公式。

```python
print("Hello, world!")
```

长度为 $n$ 的向量，时间复杂度是 $O(n)$。

$$
(a + b)_i = a_i + b_i
$$

```mermaid
flowchart LR
  A[写清问题] --> B[简单实现]
  B --> C[检查边界]
```

![图片说明](./assets/my-image.webp)

[^note]: 代码块里的 `[^1]` 不会变成脚注。
````

元信息区（两组 `---` 之间的 YAML）是可选的。未填写标题时使用正文首个一级标题，再回退到文件名；未填写摘要时使用第一段正文。`section` 可填写任意分区名称，Blog 会根据已发布文章自动创建分区，无需修改配置或 React 代码；省略或留空时归入 Learning。标签使用列表。文章按分区展示，同一分区内默认按发布日期从新到旧排列，也可在 Blog 列表中选择最早发布、最近更新或标题排序。

## 自定义分区

在 Markdown 或 HTML 文章开头填写 `section` 即可，例如：

```yaml
---
title: 最近读过的书
section: 读书笔记
---
```

发布后会自动出现「读书笔记」分区及导航入口，阅读页也会显示该分区，并支持按分区名称搜索及同分区文章翻页。其他文章使用相同的 `section` 就会归入同一分区。

- 名称必须是字符串，首尾空白会自动去除；支持中文、英文、空格及标点。包含 YAML 特殊字符时请加引号，例如 `section: "Research: AI"`。
- 自定义名称保留原有大小写，`AI` 与 `ai` 是不同分区，请统一写法。
- 兼容原有别名（不区分大小写）：`learn` / `learning` / `study` / `学习` 归入 Learning；`life` / `living` / `daily` / `生活` 归入 Life。
- 仅展示有已发布文章的分区；草稿和被排除的文件不会创建分区，移走或删除最后一篇文章后分区自动消失。
- Learning、Life 存在时保持原有顺序和介绍；自定义分区随后按名称排序，名称直接作为展示标题。保存文章后开发预览自动更新，线上发布需重新构建。

## 文章置顶

在文章开头的 YAML 元信息中声明 `pin: true`，即可让文章在 Blog 所属分类内优先显示，并带有 `Pinned` 标记。Markdown 和 HTML 文章均支持：

```yaml
---
title: 想要置顶的文章
section: 学习
pin: true
---
```

设置 `pin: false` 或省略该字段即可取消置顶。值必须是布尔值 `true` / `false`，不要加引号。置顶优先于四种排序；多篇置顶文章之间、普通文章之间分别按当前选项排序。搜索仍只显示匹配的文章，匹配结果中的置顶文章优先；`draft: true` 的文章不会因置顶而发布。置顶只影响 Blog 列表，不改变正文中的上一篇、下一篇顺序。

## 作者与邮箱

可在 Markdown 或 HTML 文件的 YAML 元信息中填写 `author` 和 `email`（字符串）。Blog 和 Notes 的列表、阅读页会显示文章自己的作者和邮箱，邮箱可点击以发送邮件。两个字段均可单独填写；省略、留空或只含空格时不显示，也不会回退到站点个人资料。

## 预计阅读时间

Blog 和 Notes 的阅读页在 `Posted on ...` 后自动显示 `About x minutes' read`，1 分钟时显示 `About 1 minute's read`，无需填写元信息。按正文（含小标题、代码和脚注）的中文汉字数与英文单词数估算：中文每分钟 350 字、英文每分钟 220 词，中英混排时将两部分耗时相加，向上取整且至少显示 1 分钟。标题、摘要等元信息、HTML 标签和页面控件不计入。

## 文末签名

Blog 与 Notes 的每篇正文末尾自动显示 Alicia 签名，采用 Allura 原始字形拆分的独立笔画轮廓，无需在 YAML 或正文中添加配置。笔画依次写出，交叉笔画共享交点但分别显露各自轮廓，先连写字母主体，再补上 `A` 的横线和两个 `i` 的点。签名每约 15.1 秒循环一次：约 6.3 秒写完，连笔处保持速度连续，转折和提笔时自然减速；写完后停留 2 秒，再沿原笔迹逆序擦除，消失后重播；首次进入视口时才创建动画，离开屏幕或切换到其他页签时暂停，返回后继续。它右对齐于正文栏末尾，位于正文之后、Blog 翻页或 Notes 反向链接之前，不会进入文章目录或改变作者字段。

签名使用独立 SVG 笔画及逐笔遮罩，随明暗主题调整颜色，窄屏自动缩放；系统开启减少动态效果时不创建动画，和打印时一样直接显示同一套完整笔画。

## 发布时间与编辑时间

Blog 和 Notes 的列表、阅读页统一显示 `Posted on YYYY-MM-DD`；有后续编辑时另显示 `Edited on YYYY-MM-DD`。日期使用语义化 `<time>` 标签，悬停可查看原始时间戳。

- `date` 表示首次发布时间，填写后优先使用。省略时沿当前分支的第一父提交链追溯 Git 历史，以文章首次进入该分支的提交作者时间作为默认发布时间；这不是部署系统记录的上线时间。
- `updated` 表示最近编辑时间，可手动指定。省略时自动使用初次提交之后最近一次修改该文章的提交时间；分支合并按合并进入当前分支的时间记录。单纯重命名、移动文件、修改文件权限或修改站点代码不会产生编辑日期。
- 同一天的后续编辑也会显示 `Edited on`。未编辑的文章只显示 `Posted on`。Git 自动时间只包含已提交的修改；预览未提交的编辑时间时可填写 `updated`。
- 两个字段支持有效的 `YYYY-MM-DD` 或带时区的 ISO 时间戳，例如 `2026-09-21T14:30:00+08:00`。页面保留时间戳所写时区的日期，不随读者的时区变动。`updated` 不可早于发布时间。
- 尚未提交的新文件或没有 Git 历史的源码副本，未填写 `date` 时使用本地文件创建日期（系统不提供创建时间时使用修改日期）供预览。为这类文件指定 `date` 可以保证不同机器上构建的日期一致。
- 自动日期需要完整 Git 历史；GitHub Pages 工作流已使用完整检出。本地浅克隆请先运行 `git fetch --unshallow`。

手动指定日期的例子：

```yaml
date: 2026-09-19
updated: 2026-09-21
```

发布后保留 `date`；需要手动维护时只更新 `updated`。

## HTML

新建 `my-html-note.html`，可以沿用相同的 YAML 元信息，再写正文片段：

```html
---
title: 用 HTML 写手记
date: 2026-09-19
description: 同样的内容，也可以用 HTML 来组织。
tags: [随记]
---

<h1>用 HTML 写手记</h1>
<p>这里是正文，支持常见的语义化 HTML 标签。</p>
<h2>一个章节</h2>
<blockquote><p>留住一个想法。</p></blockquote>
<pre><code class="language-python">print("Hello")</code></pre>
```

也接受包含 `html/head/body` 的完整文件，但网页标题、导航和主题由站点统一提供；HTML 的 `head`、脚本、样式、事件属性和 iframe 不会执行或显示。标题、段落、图片、表格、代码、`details` 等使用与 Markdown 相同的蓝白主题。不要使用内嵌 CSS/JS 构建另一套页面。

## 文章目录

正文中的 `##` / `###`（HTML 的 `h2` / `h3`）会自动生成目录，三级标题缩进显示；`h4` 至 `h6`、空标题与代码示例不进入目录。没有二、三级标题时不显示目录。

桌面端目录固定在正文右侧，随阅读高亮当前章节；目录过长时可独立滚动，并自动跟随当前项。窄屏上目录放在正文上方，保留层级和高度限制。

点击目录会平滑跳转，并将锚点写入地址栏；复制链接、刷新以及浏览器前进/后退均可定位到章节。系统开启减少动态效果时使用即时跳转。中文标题可直接使用，重复标题的锚点自动加序号；HTML 自定义 `id` 会保留，遇到重复或与正文其他锚点冲突时加序号。

## 图片、附件与互链

- 图片放在 `content/blog/assets/`，或文章附近的其他目录，通过相对路径引用。它们会随 Vite 构建打包，不依赖外部图床。
- 嵌套文章例如 `content/blog/2026/note.md`，引用共享图片时写 `../assets/my-image.webp`。
- PDF 等附件同样使用相对链接，构建时会被收录；不存在的本地附件会导致构建报错，避免发布损坏的链接。
- `/images/summer-sky.webp` 等以 `/` 开头的资源路径表示当前 User Pages 站点根目录，适合引用 `public/` 下的现有资源。
- `[另一篇](./test.md)` 会转换成对应文章详情地址，`.html` 文章也相同。指向不存在、草稿或被排除文章的互链会导致构建报错。
- 文件名决定文章地址：`content/blog/test.md` → `/blog/?post=test`；`content/blog/2026/note.md` → `/blog/?post=2026%2Fnote`。链接复制、刷新和浏览器前进/后退均不依赖服务器路由。
- 标题会自动生成目录锚点；HTML 可自定义标题 `id`。重复标题的锚点会自动加序号。
- 脚注使用 `[^标记]` 与文末的 `[^标记]: 说明`。多段脚注的续行缩进四个空格；同一脚注可以重复引用，每处都有返回链接。代码、HTML 属性与链接文字中的脚注标记保留原样。

## 草稿与文件约定

- 在元信息中添加 `draft: true`，文章及其正文不会被打包进发布页面。`true` / `false` 是布尔值，不要加引号。
- 以 `_` 或 `.` 开头的文件/文件夹，以及 `README.md`，不会被收录。
- 不要同时创建同路径同名的 `test.md` 和 `test.html`，它们会产生相同地址并导致构建报错。
- 仅支持 `.md` 与 `.html`。Markdown 中的 `$...$` 与 `$$...$$` 会在构建时渲染为公式；`mermaid` 代码块会在阅读页画成示意图。代码块里的 `$` 仍按原样显示。

网站文章可以按需删除，或设置 `draft: true`；删除时也需移除其他文章中指向它的链接。渲染测试使用测试代码中的内联样例及临时目录，不依赖 `content/blog/` 中的文章；测试样例不会发布到网站。删除全部文章或整个内容目录后仍可构建，列表会显示空状态。

## 常用元信息速查

| 字段               | 类型与默认行为                                   |
| ------------------ | ------------------------------------------------ |
| `title`            | 字符串；首个一级标题或文件名作为回退             |
| `description`      | 字符串；省略时取第一段正文的前 140 个字符        |
| `section`          | 字符串；Blog 默认 Learning，Notes 根据文件夹决定 |
| `tags`             | 字符串列表；省略时无标签                         |
| `author` / `email` | 可选字符串；留空时隐藏                           |
| `date` / `updated` | 日期或带时区时间戳；省略时按 Git 历史解析        |
| `draft`            | 布尔值，`true` 时排除发布                        |
| `pin`              | 布尔值，只影响 Blog 列表中的置顶                 |

日期、布尔值、标签和字符串类型在构建时校验。建议对带冒号等特殊字符的标题加引号；不要把布尔值写成带引号的字符串。

## 搜索与列表顺序

Blog 搜索标题、摘要、分区名称和标签，不搜索整篇正文；需要正文检索的知识资料适合放在 Notes。搜索忽略大小写与查询两端空白，使用完整子串匹配。点击标签等同于把标签填入搜索框。

搜索条件写入 `q`，排序选项写入 `sort`。默认最新发布时省略 `sort`；其余值是 `oldest`、`updated` 和 `title`。例如 `/blog/?q=AI&sort=updated` 可以直接分享。点击结果、刷新正文、返回列表时仍保留条件，浏览器历史恢复也会同步输入框和排序控件。

日期排序使用完整时间戳，置顶优先；同值按 slug 排序以保持结果稳定。正文中的上一篇、下一篇按所属分类原始发布日期顺序导航，不跟随列表筛选或置顶重排。

## 发布、迁移与删除

1. 保存文件后先在开发服务确认标题、摘要、代码与公式显示。
2. 在 `npm run preview` 的生产预览中检查正文、附件与目录链接。
3. 运行 `npm run format:check` 和 `npm run check`。
4. 提交内容和所需附件，再推送到 `main` 触发部署。

文章由草稿改为发布时，移除 `draft: true` 或改为 `false` 即可。将已发布文章改为草稿时，需要清除其他文章指向它的相对文件链接，否则构建会报告未发布目标。

移动或删除文章前，用 `rg '旧文件名|旧slug' content docs README.md` 查找引用。站内相对文章链接会经过构建校验；手写查询地址、外部网站链接和 `public/` 资源地址需要另外检查。重命名不会建立旧地址到新地址的重定向；已经对外分享的文章应尽量保留路径。

清理附件时先确认所有引用。不要仅因为附件不与文章同名就删除它；多个文章可以共享同一附件。全站重复使用的图片优先放在 `public/images/`，避免在文章目录保留同一文件的副本。

## 常见构建问题

| 提示或现象                 | 检查方法                                               |
| -------------------------- | ------------------------------------------------------ |
| 文章地址重复               | 检查同一路径下是否同时存在同名 `.md` 与 `.html`        |
| 找不到文章附件             | 按文章所在目录解析相对路径，检查大小写和文件是否已提交 |
| 链接指向不存在或未发布文章 | 检查目标移动、删除、草稿状态和相对目录层级             |
| 本地链接越过内容目录       | 专属附件移入相应集合；公共资源改用站点根路径           |
| `updated` 早于 `date`      | 修正日期或时区，或删除覆盖值让 Git 历史决定            |
| 正文加载失败               | 刷新后重试，并确认 Pages 部署完整、资源地址正确        |
| 本地日期与部署不同         | 确认 Git 历史完整；尚未提交文件可显式填写日期          |

开发中的 404 与生产预览均保留真实的 HTTP 404 状态；不存在的文章参数由 Blog / Notes 的缺失内容页面处理。不要通过删除 404 入口或关闭链接校验来绕过内容问题。
