# 如何写一篇手记

将 `.md` 或 `.html` 文件放进当前 `content/blog/` 目录（也可按年份建立子目录）。开发时保存后自动更新；发布时重新运行构建并推送即可。无需修改 React 代码或文章列表。

## Markdown

新建 `my-note.md`：

````markdown
---
title: 我的第一篇手记
author: Alicia
email: alicia@example.com
date: 2026-09-19
description: 一句话描述文章内容。
tags: [学习, 随记]
section: 学习
---

# 我的第一篇手记

从这里开始写正文。上面的同名一级标题不会在页面重复显示。

## 一个小标题

支持 **加粗**、*斜体*、[链接](https://example.com)、列表、引用、表格、任务清单、图片、脚注[^note]，以及 `$E=mc^2$` 与独立公式。

```python
print("Hello, world!")
```

长度为 $n$ 的向量，时间复杂度是 $O(n)$。

$$
(a + b)_i = a_i + b_i
$$

```mermaid
flowchart LR
  A[写清问题] --> B[简单实现]
  B --> C[检查边界]
```

![图片说明](./assets/my-image.webp)

[^note]: 代码块里的 `[^1]` 不会变成脚注。
````

元信息区（两组 `---` 之间的 YAML）是可选的。未填写标题时使用正文首个一级标题，再回退到文件名；未填写摘要时使用第一段正文。`section` 只能是预先写好的分区：`learn`（学习）或 `life`（生活），也可以直接写中文「学习」「生活」；省略时归入学习。标签使用列表。文章先按分区排列，同一分区内再按发布日期从新到旧排序；编辑不会改变文章顺序。

## 作者与邮箱

可在 Markdown 或 HTML 文件的 YAML 元信息中填写 `author` 和 `email`（字符串）。Blog 和 Notes 的列表、阅读页会显示文章自己的作者和邮箱，邮箱可点击以发送邮件。两个字段均可单独填写；省略、留空或只含空格时不显示，也不会回退到站点个人资料。

## 预计阅读时间

Blog 和 Notes 的阅读页在 `Posted on ...` 后自动显示 `About x minutes' read`，1 分钟时显示 `About 1 minute's read`，无需填写元信息。按正文（含小标题、代码和脚注）的中文汉字数与英文单词数估算：中文每分钟 350 字、英文每分钟 220 词，中英混排时将两部分耗时相加，向上取整且至少显示 1 分钟。标题、摘要等元信息、HTML 标签和页面控件不计入。

## 发布时间与编辑时间

Blog 和 Notes 的列表、阅读页统一显示 `Posted on YYYY-MM-DD`；有后续编辑时另显示 `Edited on YYYY-MM-DD`。日期使用语义化 `<time>` 标签，悬停可查看原始时间戳。

- `date` 表示首次发布时间，填写后优先使用。省略时沿当前分支的第一父提交链追溯 Git 历史，以文章首次进入该分支的提交作者时间作为默认发布时间；这不是部署系统记录的上线时间。
- `updated` 表示最近编辑时间，可手动指定。省略时自动使用初次提交之后最近一次修改该文章的提交时间；分支合并按合并进入当前分支的时间记录。单纯重命名、移动文件、修改文件权限或修改站点代码不会产生编辑日期。
- 同一天的后续编辑也会显示 `Edited on`。未编辑的文章只显示 `Posted on`。Git 自动时间只包含已提交的修改；预览未提交的编辑时间时可填写 `updated`。
- 两个字段支持有效的 `YYYY-MM-DD` 或带时区的 ISO 时间戳，例如 `2026-09-21T14:30:00+08:00`。页面保留时间戳所写时区的日期，不随读者的时区变动。`updated` 不可早于发布时间。
- 尚未提交的新文件或没有 Git 历史的源码副本，未填写 `date` 时使用本地文件创建日期（系统不提供创建时间时使用修改日期）供预览。为这类文件指定 `date` 可以保证不同机器上构建的日期一致。
- 自动日期需要完整 Git 历史；GitHub Pages 工作流已使用完整检出。本地浅克隆请先运行 `git fetch --unshallow`。

手动指定日期的例子：

```yaml
date: 2026-09-19
updated: 2026-09-21
```

发布后保留 `date`；需要手动维护时只更新 `updated`。

## HTML

新建 `my-html-note.html`，可以沿用相同的 YAML 元信息，再写正文片段：

```html
---
title: 用 HTML 写手记
date: 2026-09-19
description: 同样的内容，也可以用 HTML 来组织。
tags: [随记]
---

<h1>用 HTML 写手记</h1>
<p>这里是正文，支持常见的语义化 HTML 标签。</p>
<h2>一个章节</h2>
<blockquote><p>留住一个想法。</p></blockquote>
<pre><code class="language-python">print("Hello")</code></pre>
```

也接受包含 `html/head/body` 的完整文件，但网页标题、导航和主题由站点统一提供；HTML 的 `head`、脚本、样式、事件属性和 iframe 不会执行或显示。标题、段落、图片、表格、代码、`details` 等使用与 Markdown 相同的蓝白主题。不要使用内嵌 CSS/JS 构建另一套页面。

## 文章目录

正文中的 `##` / `###`（HTML 的 `h2` / `h3`）会自动生成目录，三级标题缩进显示；`h4` 至 `h6`、空标题与代码示例不进入目录。没有二、三级标题时不显示目录。

桌面端目录固定在正文右侧，随阅读高亮当前章节；目录过长时可独立滚动，并自动跟随当前项。窄屏上目录放在正文上方，保留层级和高度限制。

点击目录会平滑跳转，并将锚点写入地址栏；复制链接、刷新以及浏览器前进/后退均可定位到章节。系统开启减少动态效果时使用即时跳转。中文标题可直接使用，重复标题的锚点自动加序号；HTML 自定义 `id` 会保留，遇到重复或与正文其他锚点冲突时加序号。

## 图片、附件与互链

- 图片放在 `content/blog/assets/`，或文章附近的其他目录，通过相对路径引用。它们会随 Vite 构建打包，不依赖外部图床。
- 嵌套文章例如 `content/blog/2026/note.md`，引用共享图片时写 `../assets/my-image.webp`。
- PDF 等附件同样使用相对链接，构建时会被收录；不存在的本地附件会导致构建报错，避免发布损坏的链接。
- `/images/summer-sky.webp` 等以 `/` 开头的资源路径表示当前 User Pages 站点根目录，适合引用 `public/` 下的现有资源。
- `[另一篇](./test.md)` 会转换成对应文章详情地址，`.html` 文章也相同。指向不存在、草稿或被排除文章的互链会导致构建报错。
- 文件名决定文章地址：`content/blog/test.md` → `/blog/?post=test`；`content/blog/2026/note.md` → `/blog/?post=2026%2Fnote`。链接复制、刷新和浏览器前进/后退均不依赖服务器路由。
- 标题会自动生成目录锚点；HTML 可自定义标题 `id`。重复标题的锚点会自动加序号。
- 脚注使用 `[^标记]` 与文末的 `[^标记]: 说明`。多段脚注的续行缩进四个空格；同一脚注可以重复引用，每处都有返回链接。代码、HTML 属性与链接文字中的脚注标记保留原样。

## 草稿与文件约定

- 在元信息中添加 `draft: true`，文章及其正文不会被打包进发布页面。`true` / `false` 是布尔值，不要加引号。
- 以 `_` 或 `.` 开头的文件/文件夹，以及 `README.md`，不会被收录。
- 不要同时创建同路径同名的 `test.md` 和 `test.html`，它们会产生相同地址并导致构建报错。
- 仅支持 `.md` 与 `.html`。Markdown 中的 `$...$` 与 `$$...$$` 会在构建时渲染为公式；`mermaid` 代码块会在阅读页画成示意图。代码块里的 `$` 仍按原样显示。

`test.md` 是可直接在网页阅读的示例文章。确认排版后可以删除，或设置 `draft: true`。
