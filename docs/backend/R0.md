# R0：从 C/C++ 到 Rust

目标：读懂并写出普通的 Rust 代码，知道编译器为什么拒绝你的代码，以及怎么改。还不碰网络和数据库。

## 要做的事

1. 读 [The Rust Programming Language](https://doc.rust-lang.org/book/)（官方书，免费在线）第 1 到 10 章。中文版：https://kaisery.github.io/trpl-zh-cn/ 。
2. 边读边做 [Rustlings](https://github.com/rust-lang/rustlings)：

   ```bash
   cargo install rustlings
   rustlings init
   cd rustlings && rustlings
   ```

   它按章节给出一个个编译不过或测试不过的小程序，你改到通过为止。

3. 第 4 章（所有权）和第 10 章（泛型、trait、生命周期）多花些时间。只有这两章是 C++ 里没有直接对应的。

## 对照 C/C++

| Rust                                             | C/C++ 里最接近的                                   | 不同之处                                                                             |
| ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 所有权：每个值有唯一的主人，主人离开作用域时释放 | RAII、`std::unique_ptr`                            | 规则由编译器检查，没有“忘了 delete”和“删了两次”                                      |
| `let b = a;` 移走 `a`                            | `auto b = std::move(a);`                           | Rust 默认移动；移走后再用 `a`，编译不过，而不是留下一个空壳                          |
| `&T`、`&mut T` 借用                              | `const T&`、`T&`                                   | 同一时刻，要么有多个 `&T`，要么只有一个 `&mut T`。这条规则排除了数据竞争和迭代器失效 |
| 生命周期 `'a`                                    | 悬垂引用要靠自己小心                               | 编译器证明引用不会比它指向的值活得更久                                               |
| `Option<T>`                                      | 可能为空的指针、`std::optional`                    | 没有空指针。用值之前必须处理 `None`                                                  |
| `Result<T, E>` 和 `?`                            | 错误码、异常                                       | 错误是返回值的一部分，`?` 遇到错误就提前返回，相当于更简洁的 `if (err) return err;`  |
| `enum` 带数据，配合 `match`                      | `std::variant` 加 `std::visit`                     | `match` 必须覆盖所有情况，漏了编译不过                                               |
| trait                                            | 模板的约束（concepts）、纯虚基类                   | 泛型函数 `fn f<T: Trait>` 像模板，编译期展开；`dyn Trait` 像虚函数，运行期分派       |
| `Vec<T>`、`String`、`HashMap`                    | `std::vector`、`std::string`、`std::unordered_map` | `String` 一定是合法的 UTF-8                                                          |
| `&str`、`&[T]` 切片                              | `std::string_view`、`std::span`                    | 一样不拥有数据，但不会悬垂                                                           |
| `Box<T>`、`Rc<T>`、`Arc<T>`                      | `unique_ptr`、单线程的 `shared_ptr`、`shared_ptr`  | `Rc` 不能跨线程，编译器会拦住                                                        |
| cargo、crates.io                                 | CMake 加 vcpkg 或 Conan                            | 构建、依赖、测试、文档都是一个命令                                                   |
| 宏 `println!`、`vec!`                            | 预处理宏                                           | 在语法树上展开，不是文本替换，结尾的 `!` 表明它是宏                                  |

## 常见的坑

- **“borrowed value does not live long enough”：** 你返回了一个指向局部变量的引用。C++ 里这是悬垂引用，运行时才出错；Rust 在编译时拦下。通常返回拥有所有权的值（`String` 而不是 `&str`）就好。
- **“cannot borrow as mutable because it is also borrowed as immutable”：** 一边持有引用，一边修改。例如遍历 `Vec` 时往里面加元素：C++ 里会导致迭代器失效。先收集要做的改动，循环结束后再改。
- **到处 `.clone()`：** 起步时可以，先让程序跑起来；之后再想想能不能借用。
- **`unwrap()`：** 遇到 `None` 或 `Err` 就让程序崩溃。练习里可以用，服务器代码里要用 `?` 和正经的错误处理。
- **字符串索引：** `s[0]` 编译不过，因为 UTF-8 的字符长度不固定。用 `s.chars()` 或 `s.bytes()`。

## 毕业练习

做完 Rustlings 后，写一个小程序，读 [`docs/api/fixtures/private/manifest.json`](../api/fixtures/private/manifest.json)，按等级列出页面：

```
public:
  /blog/contract-open/  An open page  (2026-01-02)
friends:
  /blog/contract-friends/  For friends  (2026-01-03)
family:
  /notes/contract-family/  For family  (2026-01-04)
```

要用到：

- `cargo new manifest-list`，在 `Cargo.toml` 里添加 `serde`（带 `derive` 功能）和 `serde_json` 两个依赖；
- 用 `#[derive(Deserialize)]` 定义和清单对应的结构体，`level` 是 `Option<String>`；
- 用 `std::fs::read_to_string` 读文件，`serde_json::from_str` 解析，失败时打印清楚的错误，而不是 `unwrap()` 崩溃；
- 用 `levels` 的顺序决定输出顺序。

这个程序在 R4 还能用上：后端读私有目录时，结构体是一样的。写完可以发给 Claude 审阅，重点看所有权和错误处理的写法。
