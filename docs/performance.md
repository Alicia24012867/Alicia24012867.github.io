# 性能与验证

本轮于 2026-09-21 使用 Node.js 24.14.0 测量，基线为提交 `aaed459`。历史优化记录可从 Git 历史查看；本页保留当前结构、可复现命令与本轮数据。

## 本轮变化

- Blog/Notes 共用内容路由、页面元信息、正文异步加载和失败状态；三个入口共用站点布局与页脚。
- 内容组件集中在 `src/content/`，阅读器集中在 `src/content/reader/`；首页入口移到 `src/home/main.tsx`。
- 内容索引在一次遍历中建立地址查找与分组；匹配文本在首次非空搜索时整理，每篇只整理一次。浏览列表和直接读正文不做这项工作。
- Notes 等待全文索引期间不再计算不会显示的摘要搜索结果。列表保留分组级缓存，移除每行重复的 `memo` 比较。
- 构建验证与包体积报告合并到 `scripts/verify-build.mjs`，共用依赖图遍历。

## 搜索基准

`benchmark-search.mjs --compare-ref aaed459` 将历史与当前索引实现用于相同的 10,000 篇模拟笔记，每篇含 1,220 个正文字符，4% 的标题包含 `CUDA memory`。两种实现先预热，再交替顺序运行九次，表中为各阶段中位数。计时之外将搜索结果与独立的完整子串匹配结果比较。

| 阶段                     | 重构前（ms） | 重构后（ms） |
| ------------------------ | -----------: | -----------: |
| 列表索引初始化（摘要）   |        1.924 |        0.465 |
| 全文索引初始化           |        4.858 |        0.446 |
| 初始化后的首次全文搜索   |        4.898 |        7.698 |
| 全文初始化 + 首次搜索    |        9.802 |        8.117 |
| 已有缓存的 14 次连续查询 |       21.439 |       21.425 |

列表初始化耗时减少约 76%。文本整理被延迟到首次搜索，因此单看首次过滤会变慢；包含初始化的首次搜索总耗时在本次测量中减少约 17%，后续搜索基本持平。总耗时单独取中位数，不等于两个阶段中位数之和。

连续查询覆盖输入、大小写与空格规范化、删除、替换、无结果和清空。相同规范化查询复用结果，更具体的查询仅过滤上次命中的文章。此基准只衡量同步索引与过滤，不包含下载、React 渲染或浏览器输入延迟。当前站点只有少量示例内容，实际收益远小于万篇模拟数据；绝对耗时随机器负载与垃圾回收变化。

## 验证与复现

```sh
npm run check
npm run format:check
npm run bundle:report
node --experimental-strip-types scripts/benchmark-search.mjs --compare-ref aaed459
node scripts/benchmark-content.mjs
node scripts/benchmark-content.mjs --long
```

对其他构建目录运行 `node scripts/verify-build.mjs --report /path/to/dist`。搜索基准可比较重命名前后的索引文件；内容编译基准的 `--compare-ref` 仅比较历史 catalog 实现，不代表完整历史构建性能。

49 项测试、TypeScript、格式检查、生产构建及懒加载依赖检查通过。新增测试验证浏览阶段不读取搜索字段，并且后续查询只整理每篇文本一次。浏览器检查涵盖首页、Blog 标签筛选、Notes 正文关键词搜索与无结果状态、正文加载、刷新后返回筛选结果、目录跳转、公式、Mermaid 和缺失文章页面。捕获的浏览器警告与错误日志为空。未测量生产网络时延或 Core Web Vitals。
