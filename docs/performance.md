## 清理与结构调整

## 运行与编译优化

### 列表排序

先为每篇文章解析日期，再排序。日期解析从比较器中的重复操作变成每篇一次；排序本身仍为 O(n log n)，临时日期缓存为 O(n)。置顶优先、时间戳与时区比较、编辑时间回退、同值 slug 排序和输入不可变行为保持一致。标题排序不创建日期缓存。

测量采用相同的 10,000 篇模拟文章，包含置顶、重复标题、不同发布日期和部分编辑日期。每种实现预热三次，然后交替运行 11 轮，取中位数。计时前逐项比较四种排序的完整结果。

| 排序方式 | 重构前（ms） | 重构后（ms） |
| -------- | -----------: | -----------: |
| 最新发布 |       71.719 |       13.535 |
| 最早发布 |       70.513 |       13.084 |
| 最近更新 |       73.473 |       14.374 |
| 标题     |       19.962 |       19.945 |

日期排序在该样本中减少约 80% 的处理时间，标题排序基本不变。当前网站仅有少量文章，实际绝对收益很小；该结果不代表整页加载速度或网络性能。

复现：

```sh
node --experimental-strip-types scripts/benchmark-sort.mjs --compare-ref a1d9dd5
```

不带 `--compare-ref` 时仅测量当前版本。Git 比较需要保留基线提交。

### 内容生成

- 纯文本提取在一次 HTML 清洗中删除脚注引用并展开普通上标，省去第二次完整解析；标题的纯文本不再重复提取。
- 没有附件的正文模块直接导出数据，不再生成空 URL 表或运行无效的替换表达式。
- 正文加载函数表在首次读取文章时才创建，列表浏览无需初始化该表。
- 内容目录为空或缺失时返回空集合并清理旧编译缓存；文件重建后恢复发现、全文搜索与正文加载。

使用同一组 40 篇文本（清理前八篇内容和 32 篇混合语法样例）比较完整编译结果，输出一致。11 轮交替测量中位数约为 166.2 → 162.7 ms，差异较小，因此不据此宣称整体构建有显著加速。

### 文末签名

- 屏外初始状态不创建动画，也不计算关键帧；首次进入视口且页面可见时才初始化。
- 关键帧按需计算并在模块内复用，切换减少动态效果或再次挂载时不用重新计算。
- 动态、减少动态效果和打印共用同一组 16 条墨迹路径，删除重复的静态 SVG 路径。
- 约 6.3 秒完成书写，停留两秒，再严格镜像擦除；约 15.1 秒循环。A/l 的连续曲线与已调整的书写节奏保留。
- 离开视口或切换页签时暂停；减少动态效果时取消动画，通过 CSS 去掉遮罩显示完整签名。

## 第三轮：分享图与静态分享地址

## 第四轮：算法与重复工作

基线提交为 `ad44b7a`，本地测量环境为 Node.js 24.14.0。页面外观、样式与分享卡片像素保持不变，已提交的卡片无需重新生成。

### 静态分享页

- 原实现为每篇文档在整份入口 HTML 上依次执行十余次正则替换，成本约为 O(n·k·S)（n 篇文档、k 个标签、外壳长度 S）。现在每个入口外壳只编译一次：按原顺序逐个定位标签并留下占位，再拆成静态片段；每篇文档只拼接片段与渲染值，成本降为 O(k·S + n·S)。
- 匹配顺序、重复标签只替换第一个、Prettier 换行后的 `<noscript>`、缺少标签时的报错与原实现一致；外壳含 NUL 字符时拒绝编译。缺少分享图仍先于外壳问题报告。
- 开发与预览服务器按 slug 直接查找文档，不再遍历目录。

使用生产构建的 Blog 入口外壳（3,134 字节）渲染 10,000 篇模拟文档，预热三次后交替运行 11 轮取中位数；计时前逐页比较两版输出。

| 项目            | 重构前（ms） | 重构后（ms） |
| --------------- | -----------: | -----------: |
| 10,000 个分享页 |        278.5 |         69.8 |

### 列表排序

日期排序先为每篇文章计算一次置顶标记与时间戳，再排序并还原（decorate–sort–undecorate），比较器只比较数字，不再查询日期缓存表。标题排序直接比较。曾尝试把 slug 同值比较换成缓存的 `Intl.Collator`，在 ASCII slug 上反而约慢 3 倍（20 万次比较 7.8 ms 对 2.3 ms，V8 的 `localeCompare` 有快速路径），因此保留 `localeCompare`。

### 目录锚点与脚注

重复标题和同名脚注原先每次从 `-2` 起逐个试探，k 个同名标题共需 O(k²) 次查找。现在为每个基名记住下一个候选后缀，总体为 O(k)。已占用集合只增不减，跳过的后缀不会重新可用，因此结果与逐个试探完全一致；标题自身写明的 id 仍可保留。新增随机序列对照测试，以及 300 个同名标题与碰撞脚注的长例。

### 分享卡片

- 背景裁切与两次半透明叠加每次运行只做一次，各卡片复制同一张底图。
- 标题省略由逐字反复测量整段文字改为累加前缀宽度。Pillow 的字形前进宽度是 1/64 像素的整数倍，累加结果与整段测量相同。
- 本机渲染 9 张卡片（6 张已提交卡片与 3 个省略边界样例）由约 436 ms 降至 255 ms（单次测量，含 Python 启动），JPEG 输出与原渲染器逐字节一致。
- 清理过期卡片时一并删除变空的上级目录；此前多层目录只删除最内层。

### 其他

- `verify-build` 每个文件只读取并压缩一次，入口 HTML 只读取一次；检查与报告结果不变。
- 地址解码统一为 `decodeSlug`，页面路由、内容目录与分享页共用；畸形转义一律视为未找到。
- 开发服务器的订阅、sitemap 与 robots 共用一个响应函数；sitemap、Atom 与分享页共用同一个最后修改时间计算。
- 链接分组与首页锚点列表在模块加载时计算一次，不再在每次渲染时重复过滤。
